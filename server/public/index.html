self-check for CVE-2026-109618 and CVE-2026-109619

Is your website exposed to PHP2Shell?

PHP2Shell is a pair of critical PHP flaws, CVE-2026-109618 and CVE-2026-109619. Enter your site to compare its reported PHP versions with the fixed releases and, with your permission, inspect session-handling behaviour.

CVE-2026-109618 and CVE-2026-109619 were first fixed in PHP 8.2.35, 8.3.36, 8.4.27 and 8.5.12. Version evidence is compared with these releases for both CVEs. The session check does not verify either complete fix, and no memory-exhaustion or exploit test is run. Vendor backports may keep an older version number.

Exploitation attempts began on 17 October 2026, four days before the fix was released, as Amazon reports. The Delft Threat Intelligence Lab tracks the attacks it sees.

Only public domain names and public IP addresses are checked, on ports 80, 443, 8080 and 8443.

What the check does

It fetches your start page as a browser would, plus at most two PHP pages it links to, and reads the PHP version the server advertises. That version is compared with the releases that carry the fix.

If you confirm that the site is yours, it sends small requests to the candidate PHP paths and records session warnings for each URL. These warnings are patch-associated indicators, not proof of the complete fixes. A changed session response on one path never overrides an older PHP version found on another. The about page explains more.

What it cannot see

A hardened server advertises no version and shows no errors. Distributions such as Ubuntu and Red Hat also fix PHP without changing the version number. A result without a finding is therefore not proof of safety. Only a check on the server itself is conclusive.

If your site runs PHP

  • Upgrade PHP to 8.5.12, 8.4.27, 8.3.36 or 8.2.35, or install your vendor's fixed package.
  • Restart every PHP worker afterwards, so the old code is no longer running.
  • If you cannot upgrade at once, take the site offline until it is fixed, as CISA, the NCSC and CERT-EU advise. The PHP security advisory lists interim measures, which are partial.
  • Look for signs of compromise since 17 October 2026, since upgrading does not remove a backdoor: PHP workers that started shells or downloaded tools, unexpected processes, and changed files. The Delft dashboard lists the download addresses and malware hashes seen in attacks.
